# نتیجهٔ اجرای کارهای فوری

۴ اکتبر ۲۰۲۶ — دامنه: موارد ۱، ۲، ۳، ۴، ۵، ۶ و ۱۶ از فهرست بررسی عمیق.

## کارهای انجام‌شده

- [x] **کنترل ورود و مصرف:** نشست امضاشده برای ساخت بازی آنلاین، کنترل Origin، سقف ساخت در ساعت و روز، تعداد بازی هم‌زمان، محدودیت تصمیم هر عامل و عمر ۲۴ساعتهٔ بازی. سهمیه و شمارندهٔ مصرف بعد از restart حفظ می‌شوند. درخواست اضافه پیش از ساخت runner رد می‌شود. مقدار صفر در بودجهٔ HTTP دیگر به معنی نامحدود نیست.
- [x] **رأی‌گیری:** پنل تصمیم بالاتر از کارت‌ها قرار می‌گیرد و منوی اعتماد کلیک را دریافت می‌کند. با CSS قبلی آزمون دقیقاً به علت دریافت کلیک توسط کارت Vittorio شکست خورد؛ با CSS اصلاح‌شده موفق شد.
- [x] **تحمل خرابی گزارش:** خطای نوشتن audit مانع پذیرش یا ادامهٔ اقدام نمی‌شود. ثبت گزارش اقدام انسان پس از ذخیرهٔ موفق انجام می‌شود. شکست ذخیرهٔ اصلی، خود اقدام را برمی‌گرداند و همان درخواست قابل تلاش مجدد است.
- [x] **ذخیره و ادامه در Python:** snapshot نسخه‌دار در SQLite شامل نقش‌ها، توکن‌ها، پرسش‌ها، اقدامات شب، transcript، حافظه و باورهای عامل‌ها، شمارندهٔ مصرف و رسید اقدامات ذخیره می‌شود. مالکیت تک‌فرایندی از اجرای هم‌زمان دو نویسنده جلوگیری می‌کند. بازی در فرایند جدید با همان وضعیت بازیابی می‌شود؛ تصمیم در حال اجرا با بودجهٔ ازقبل ثبت‌شده ادامه می‌یابد.
- [x] **اتصال و ارسال مطمئن:** deadline پانزده‌ثانیه‌ای برای هدر و بدنهٔ پاسخ؛ تلاش مجدد اتصال با فاصلهٔ ۱ تا ۱۵ ثانیه؛ رسید پایدار برای جلوگیری از اجرای دوبارهٔ اقدام؛ رد وضعیت قدیمی. نشست نامعتبر از چرخهٔ تلاش مجدد خارج می‌شود.
- [x] **حفظ کار بازیکن:** متن صحبت/پاسخ، انتخاب مخاطب و انتخاب‌های رأی در همان بازی و نوبت حفظ می‌شوند. خانه بازی را لغو نمی‌کند؛ «ادامهٔ بازی» و «پایان دادن به بازی» جدا هستند. شکست لغو بازی حتی در تلاش مجدد، موفقیت تلقی نمی‌شود.
- [x] **آزمون مرورگر واقعی:** Playwright روی Chrome؛ انتخاب‌گر روی کارت، پاسخ بلند در عرض ۳۹۰ پیکسل، منشن و پیش‌نویس پس از refresh، درخواست معلق، پایان یک بازی آفلاین از طریق UI، و گم‌شدن پاسخ اقدام پذیرفته‌شده. workflow اجرای آزمون‌ها در GitHub اضافه شده است؛ اجرای راه‌دور CI هنوز انجام نشده است.

## شواهد آزمون

- ۹۴ آزمون Python موفق، شامل تزریق OSError، rollback، رسید تکراری پس از restart، بازیابی در فرایند Python جداگانه، سقف و مجوز ساخت، مالکیت انحصاری پایگاه داده و ادامهٔ تصمیم نیمه‌تمام.
- ۲۸ آزمون کنترلر JavaScript موفق.
- ۶ آزمون مرورگر واقعی موفق؛ شامل یک مسابقهٔ کامل آفلاین.
- کنترل منفی CSS قدیمی: شکست مورد انتظار با پیام `Vittorio Moretti ... intercepts pointer events`.
- هیچ درخواست مدل آنلاین یا استقرار عمومی انجام نشده است.

## شرایط اجرا

ذخیرهٔ پایدار فعلی برای **سرور Python با یک worker و دیسک پایدار** است. مسیر پیش‌فرض `.palermo-data/games.sqlite3` است؛ این پوشه در Git ثبت نمی‌شود. برای انتشار عمومی `PALERMO_PLAY_KEY` لازم است. برای اجرای مستقیم محلی می‌توان `PALERMO_ALLOW_LOCAL_LIVE=1` را فعال کرد. جزئیات سهمیه‌ها و فرمان آزمون در README و `.env.example` آمده است.

**Cloudflare هنوز میزبان پایدار بازی نیست.** ساخت بازی در Worker با ۵۰۳ رد می‌شود؛ پشتیبانی از Durable Object و زمان‌بندی اجرای آن، کار جداگانه‌ای است. پیش‌نمایش فایل‌های رابط همچنان قابل استفاده است. این گزارش ادعای تکمیل یا آزمون زیرساخت Cloudflare ندارد.

بازگشت به خانه اجرای عامل‌ها را متوقف نمی‌کند؛ آن‌ها تا نوبت انسان یا پایان عمر بازی ادامه می‌دهند. بازی‌هایی که پیش از این اصلاحات فقط در حافظهٔ سرور قدیمی بوده‌اند، پس از خاموش‌شدن آن سرور قابل بازیابی نیستند. محدودیت‌ها سقف درخواست و توکن هستند و سقف ریالی/دلاری صورتحساب محسوب نمی‌شوند.

موارد P2 شامل سوگیری fallback، کیفیت استدلال، حافظهٔ شاهددار، پاک‌سازی آرشیو و جزئیات دفتر وقایع، طبق فهرست اصلی باز مانده‌اند.

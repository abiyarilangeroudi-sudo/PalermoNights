هر ۹ یافته گزارش اولیه در نسخه کاری اصلاح شد. تغییرات موجود کاربر حفظ شدند؛ commit یا انتشار انجام نشده است.

| مورد | اصلاح انجام‌شده |
| --- | --- |
| افشای نقش در وضعیت اجرا | شناسه و نام اقدام خصوصی، نوبت‌های اختصاصی و جزئیات خطای عامل از پاسخ عمومی و SSE حذف شدند. حتی وضعیت «منتظر انسان» فقط با توکن همان انسان نمایش داده می‌شود تا رئیس مافیا در شب اول از این راه شناسایی نشود. |
| پیش‌بینی نقش با seed | هر سه API ایجاد بازی، seed ارسالی را رد می‌کنند. نقش‌های بازی واقعی با تصادف سیستم در سرور تعیین می‌شوند؛ seed صرفاً در موتور داخلی برای تست و شبیه‌سازی باقی مانده است. |
| توقف بر اثر ترتیب HTTP/SSE | همه اقدام‌های رابط از یک مسیر هماهنگ عبور می‌کنند. پس از پایان درخواست، وضعیت تازه فوراً مسیریابی می‌شود؛ پیشروی دیگر منتظر رویداد بعدی نیست. ارسال تکراری هم‌زمان نیز مهار شد. |
| لغو بدون مجوز | لغو بازی تعاملی به توکن انسان و لغو مسابقه AI به control_token مستقل نیاز دارد. توکن اشتباه یا متعلق به بازی دیگر رد می‌شود. |
| ناسازگاری مسیرهای اقدام | مسیر عمومی اقدام، بازی‌های مدیریت‌شده توسط runner را پیش از تغییر موتور رد می‌کند. بازی تعاملی از مسیر هماهنگ `/interactive/action` ادامه می‌یابد. |

| انتظار بی‌پایان پس از شکست | وضعیت FAILED/CANCELLED پیام روشن و گزینه بازی جدید دارد. خطای موقت اتصال هنگام بازیابی قابل تلاش مجدد است؛ نشست منقضی پاک می‌شود. |
| ردشدن نتیجه نهایی | نتیجه رأی و شب تا تأیید بازیکن حفظ می‌شوند؛ اعلام برنده اسلاید در حال خواندن را قطع نمی‌کند. تأیید نتایج نیز در نشست ذخیره می‌شود. |
| تحقیق تکراری کارآگاه fallback | اهداف تحقیق‌نشده و قانونی با اولویت عدم‌قطعیت انتخاب می‌شوند؛ اگر همه اهداف شناخته شده باشند، همچنان یک اقدام قانونی تولید می‌شود. |

## شواهد اعتبارسنجی

- **۴۹ آزمون Python موفق**، شامل آزمون‌های جدید محرمانگی، مجوز لغو، seed، جلوگیری از ناهماهنگی runner و انتخاب هدف کارآگاه.
- **۱۳ آزمون JavaScript موفق** برای ترتیب‌های مختلف رسیدن HTTP/SSE، خطا و تلاش مجدد، جلوگیری از ارسال هم‌زمان، بازیابی نشست و نمایش نتیجه نهایی.
- **۵۰۰ مسابقه آفلاین از ۵۰۰ مورد تمام شدند**؛ بدون exception یا توقف runner، حداکثر ۷ دور. نتایج این نمونه: ۴۱۴ برد مافیا و ۸۶ برد شهروند. این نسبت معیار تعادل قوانین یا کیفیت مدل زنده نیست.
- در مرورگر واقعی، مسابقه با **تأخیر ۱٫۵ ثانیه‌ای پاسخ اقدام** از ادعا، گفت‌وگو، رأی‌گیری و شب عبور کرد و تا برنده نهایی ادامه یافت.
- refresh در رأی‌گیری همان مسابقه را بازیابی کرد. refresh روی نتیجه شب نیز همان نتیجه خوانده‌نشده را حفظ کرد، حتی وقتی سرور در ادامه مسابقه جلو رفته بود.
- `git diff --check` و بررسی syntax فایل JavaScript موفق بودند.

اجرای آزمون‌ها از ریشه پروژه:

```sh
.venv/bin/pytest
node --test tests/frontend.test.cjs
```

## تغییرات قرارداد API

- فیلد `seed` از درخواست‌های ایجاد بازی حذف شده است؛ ارسال آن پاسخ ۴۲۲ می‌گیرد.
- خواندن `run-state` با `X-Player-Token` معتبرِ انسان، وضعیت انتظار واقعی انسان را برمی‌گرداند. نسخه بدون توکن و SSE فقط پیشرفت عمومی را نشان می‌دهند. اقدام‌های مجاز از observation خصوصی گرفته می‌شوند.
- لغو مسابقه تعاملی با `X-Player-Token` انجام می‌شود. ایجاد مسابقه صرفاً AI یک `control_token` برمی‌گرداند که برای لغو باید در `X-Run-Token` فرستاده شود.
- برای بازی‌های مدیریت‌شده توسط runner، مسیر عمومی اقدام پاسخ ۴۰۹ با `USE_INTERACTIVE_ACTION_ENDPOINT` می‌دهد. از مسیر تعاملی استفاده شود.

این تغییرات در README نیز مستند شده‌اند. نسخه URL فایل JavaScript تغییر کرده است تا رابط قدیمیِ cacheشده درخواست ناسازگار نفرستد.

## حدود اعتبارسنجی

همه آزمون‌ها آفلاین بودند و در بررسی مرورگر نیز ارائه‌دهنده خارجی غیرفعال بود؛ هزینه مدل ایجاد نشد. بازیابی مرورگر به باقی‌بودن بازی در حافظه سرور وابسته است. پایداری پس از restart سرور، استقرار چند worker و کیفیت پاسخ مدل‌های زنده خارج از این ۹ اصلاح‌اند و در این مرحله تغییر نکردند.

فایل `REPORT.fa.md` و اسکریپت‌های `reproduce_*` سند وضعیت پیش از اصلاح هستند؛ assertionهای آن اسکریپت‌ها وجود باگ قدیمی را بررسی می‌کنند و آزمون موفقیت نسخه اصلاح‌شده نیستند. آزمون‌های معتبر اصلاحات در پوشه `tests` قرار دارند.
